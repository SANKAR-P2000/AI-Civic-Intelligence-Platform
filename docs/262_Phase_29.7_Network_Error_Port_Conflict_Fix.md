# Phase 29.7 – "Network Error" Fix: Stale Backend Process / Port 8080 Conflict

## Status

- Phase 29.6 – Admin UI, File Upload & Integration Bug Fixes: ✅ Completed
- Phase 29.7 – "Network Error" Fix (Port 8080 Conflict): ✅ Completed

---

# 1. Symptom

When the user signed in or created an account in the browser, the frontend
showed:

```
Network error. Please check your connection.
```

This happened even though both the frontend (Vite on `:5173`) and the backend
project were being run.

---

# 2. Root Cause

The backend failed to start with:

```
APPLICATION FAILED TO START
Web server failed to start. Port 8080 was already in use.
```

Diagnosis:

1. A **stale `java.exe` process (PID 21068)** was still running the `AICIP`
   backend and was **holding port 8080**.
2. This stale process had been started **before the latest code changes**
   (e.g., the `ComplaintServiceImpl` relative image URL fix and the admin UI
   features).
3. When the user tried to start the backend again (from IntelliJ IDEA), the
   new instance could **not bind to port 8080** because the old process still
   held it.
4. The frontend's `/api` proxy forwarded to `:8080`, which was being served by
   the **outdated** backend — so authentication (`/api/users/login`), which
   depended on the latest endpoint behavior, returned errors and the browser
   surfaced them as a generic "Network error."

---

# 3. How It Was Fixed

## 3.1 Identify the process holding the port

```bash
netstat -ano | findstr :8080
```

Result showed a `LISTENING` entry owned by PID **21068**.

## 3.2 Confirm it was the stale backend

```bash
tasklist /FI "PID eq 21068"
```

Result: `java.exe` (the old Spring Boot backend).

## 3.3 Terminate the stale process

```bash
taskkill /PID 21068 /F
```

This freed port 8080.

## 3.4 Start a fresh backend with the latest code

```bash
cd backend
mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

The new instance (PID 7192) bound to port 8080 successfully using the
`local` profile (real MySQL credentials).

---

# 4. Verification

After the fix, the full stack was verified end-to-end:

| Check                                               | Result              |
| --------------------------------------------------- | ------------------- |
| Frontend dev server `http://localhost:5173`         | `200` ✅            |
| Backend `POST /api/users/login` (direct, bad creds) | `401` (expected) ✅ |
| Frontend proxy `POST /api/users/login` (via :5173)  | `401` (expected) ✅ |

The `401` responses prove the backend is reachable and correctly validating
credentials — the exact path the browser uses now works.

---

# 5. Prevention

- When port `8080` is already in use, stop the existing process before
  starting a new backend instance.
- Use `netstat -ano | findstr :8080` to find the PID, then
  `taskkill /PID <pid> /F`.
- In IntelliJ, ensure the previous run has stopped (or use the "Stop" button)
  before re-running to avoid orphaned processes.

---

# 6. Architecture Note

```text
Browser (React :5173)
      │  /api  (Vite dev proxy)
      ▼
Spring Boot backend :8080  ◄── must be the LATEST build, bound to 8080
      │  JDBC
      ▼
MySQL aicip_db :3306 (local profile)
```

If any layer is missing or running stale code, the chain breaks and surfaces
as a "Network error" in the browser.
