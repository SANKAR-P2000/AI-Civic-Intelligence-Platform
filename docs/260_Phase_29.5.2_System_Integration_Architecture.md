# 4. Request Flow (Real-Time)

## 4.1 Authentication Flow

1. **Register / Login** — `Login.jsx` / `Register.jsx` call `authService`
   which posts to `/api/users/register` or `/api/users/login`.
2. Backend validates credentials, returns a JWT access token and a refresh
   token.
3. Frontend stores tokens in `localStorage` via `tokenStore`.
4. `AuthContext` restores the session on reload by calling `/api/users/me`.
5. On a `401`, the API client (`api.js`) automatically refreshes the token
   via `/api/auth/refresh`.

## 4.2 Complaint Flow (Citizen)

1. `Complaints.jsx` submits a complaint to `POST /api/complaints`
   (requires `CITIZEN` role).
2. Backend saves it to the `complaints` table and sends an email
   notification.
3. `Dashboard.jsx` loads the citizen's complaints via
   `GET /api/complaints/my` and personal stats via
   `GET /api/dashboard/mystats`.

## 4.3 Public Tracking Flow

1. An unauthenticated visitor enters a complaint ID on the Home page.
2. `Home.jsx` calls `GET /api/complaints/track/{id}` (now public).
3. The backend returns the complaint details; the visitor is redirected to
   `/complaints?track={id}` to view the live status.

## 4.4 Admin Flow

1. Admin logs in and lands on the dashboard.
2. `Dashboard.jsx` calls `GET /api/admin/complaints` and
   `GET /api/admin/dashboard` (both require `ADMIN`).
3. Admin analytics, status updates, and search use the `/api/admin/**`
   family of endpoints.

# 5. Security Architecture

## 5.1 JWT Authentication

- `JwtAuthenticationFilter` intercepts each request.
- Extracts the `Authorization: Bearer <token>` header.
- Validates the token and loads user authorities via
  `CustomUserDetailsService`.
- Sets the `SecurityContext` for downstream `@PreAuthorize` checks.

## 5.2 Public Endpoints (permitAll)

| Endpoint                            | Purpose                   |
| ----------------------------------- | ------------------------- |
| `/api/users/register`               | Registration              |
| `/api/users/login`                  | Login                     |
| `/api/auth/**`                      | Refresh / logout          |
| `/api/complaints/track/**`          | Public complaint tracking |
| `/uploads/**`                       | Static complaint images   |
| `/swagger-ui/**`, `/v3/api-docs/**` | API documentation         |

## 5.3 Role-Based Access

| Role         | Can access                                                |
| ------------ | --------------------------------------------------------- |
| `CITIZEN`    | Create complaints, own complaints, own stats              |
| `ADMIN`      | All `/api/admin/**`, all complaints, dashboard, analytics |
| `GOVERNMENT` | Dashboard stats, all complaints, status updates           |

# 6. Database Integration

## 6.1 Connection

- Active profile: `local` (`spring.profiles.active=local`).
- Loads `application-local.properties` with real MySQL credentials.
- JPA `ddl-auto=update` keeps the schema in sync with the entities.

## 6.2 Core Tables

| Table            | Entity         |
| ---------------- | -------------- |
| `users`          | `User`         |
| `complaints`     | `Complaint`    |
| `refresh_tokens` | `RefreshToken` |
