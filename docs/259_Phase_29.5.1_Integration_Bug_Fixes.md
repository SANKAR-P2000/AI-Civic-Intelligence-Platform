# 2. Bugs Identified & Fixed

## Bug 1 – Complaint Images Blocked by Security

**Problem:**
`/uploads/**` is served by `WebConfig` as a static resource handler, but
`SecurityConfig` did not include it in `.permitAll()`. As a result, every
complaint image request returned `403 Forbidden`.

**Fix:**
Added `/uploads/**` to the permitted request matchers in `SecurityConfig`.

```java
.requestMatchers(
        "/swagger-ui/**",
        "/swagger-ui.html",
        "/v3/api-docs/**",
        "/uploads/**",
        "/api/users/register",
        "/api/users/login",
        "/api/auth/refresh",
        "/api/auth/logout",
        "/api/auth/**")
.permitAll()
```

## Bug 2 – Citizen Dashboard Stats Returned 403

**Problem:**
`Dashboard.jsx` fetched `/dashboard/stats` for citizens, but that endpoint is
`@PreAuthorize("hasAnyRole('ADMIN','GOVERNMENT')")`. Citizens therefore
received `403 Forbidden` and their dashboard stats never rendered.

**Fix:**
Added a citizen-scoped statistics endpoint and wired the frontend to use it.

- `ComplaintRepository`: added `countByCitizen(...)` and citizen-scoped
  `countByCategory`/`countByStatus` helpers.
- `DashboardService`: added `getMyStatistics()`.
- `DashboardServiceImpl`: implemented `getMyStatistics()`.
- `DashboardController`: added `GET /api/dashboard/mystats`.
- `frontend/src/services/complaints.js`: added `getMyStats()`.
- `frontend/src/pages/Dashboard.jsx`: uses `getMyStats()` for citizen role.

New controller endpoint:

```java
@GetMapping("/mystats")
@PreAuthorize("hasRole('CITIZEN')")
public DashboardStatisticsResponse getMyStatistics() {
    return dashboardService.getMyStatistics();
}
```

## Bug 3 – Public Complaint Tracking Broken

**Problem:**
The Home page exposes a public "Track Complaint" widget, but
`ComplaintController.trackComplaint` was annotated
`@PreAuthorize("isAuthenticated()")`. Unauthenticated visitors could not
track complaints, and the widget always failed.

**Fix:**
Removed the authentication requirement from the track endpoint so it is
publicly accessible.

```java
@GetMapping("/track/{id}")
public ComplaintResponse trackComplaint(@PathVariable Long id) {
    ...
}
```

---

## Bug 4 – Backend Could Not Connect to the Database

**Problem:**
`application.properties` contained placeholder credentials
(`your_mysql_username` / `your_mysql_password`) and no active profile. The
real credentials lived in `application-local.properties` but the `local`
profile was never activated, so the backend could not connect to MySQL.

**Fix:**
Activated the `local` profile and used the real database credentials in
`application.properties`.

```properties
spring.profiles.active=local
spring.datasource.url=jdbc:mysql://localhost:3306/aicip_db
spring.datasource.username=root
spring.datasource.password=admin@SANKAR2000
```

---

## Bug 5 – `VITE_API_BASE_URL` Not Documented

**Problem:**
The frontend API base URL defaulted to `/api` (via the Vite proxy) but the
environment variable was not documented in `.env.example`.

**Fix:**
Created `frontend/.env.example` documenting `VITE_API_BASE_URL`.
