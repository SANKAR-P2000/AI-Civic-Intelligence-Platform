---

# 1. Symptom

In **daylight mode**, on the **Sign In** and **Create Account** forms:

- The field **labels** (e.g. "Email Address", "Password") were hard to see /
  appeared almost invisible against the light card background.
- The required-field **`*`** marker was not clearly visible.
- The same text was perfectly readable in **night mode**.

Night mode worked because the base CSS tokens default to the dark palette
(white text). Daylight mode re-themes the card/background but the form label
and asterisk were still using the **fixed dark-palette** colors.

---

# 2. Root Cause

The reusable `Input` component stylesheet
(`frontend/src/components/ui/Input.css`) had **two color systems**:

1. The base rules used the **fixed** `--color-*` tokens defined in `:root`
   (dark theme values, e.g. `--color-text-primary: #f8fafc` = near-white).
2. A **theme override** block at the bottom re-themed only the **input field**
   (`--theme-surface`, `--theme-text-primary`, `--theme-text-muted`), but did
   **not** override the **label**, **required asterisk**, or **error text**.

So in daylight mode:

- The label stayed white (`#f8fafc`) on a light `--theme-surface` → invisible.
- The required `*` used `--color-danger` (`#ef4444`) which, combined with the
  invisible label, was effectively not visible to the eye.

Other components (Navbar, Footer, StatCard, SectionHeading, ComplaintCard,
Dashboard, Complaints) already use `--theme-*` tokens and were correct.

---

# 3. How It Was Fixed

In `frontend/src/components/ui/Input.css`, added theme-aware overrides for the
label, required asterisk, error, and helper text so they respond to the active
theme:

```css
.aicip-field__label {
  color: var(--theme-text-primary);
}

.aicip-field__required {
  color: var(--theme-danger);
}

.aicip-field__error {
  color: var(--theme-danger);
}

.aicip-field__helper {
  color: var(--theme-text-muted);
}
```

Because these overrides come **after** the base rules (same specificity, later
in source order), they win and correctly theme the text in both daylight and
night mode.

This also fixes the same labels on the **Complaints** form (which uses the
shared `aicip-field` classes for its textarea/select) and the **Admin**
complaints search input.

# 4. How to Use the Website via Localhost (IntelliJ + VS Code)

This project uses **two separate processes** that talk to each other over
localhost. You run the **backend from IntelliJ IDEA** and the **frontend from
VS Code**, exactly as you are doing.

## Prerequisites

- MySQL is running locally, and database `aicip_db` exists.
- Backend real credentials are in `backend/src/main/resources/application-local.properties`
  (username `root`, your password).
- The `local` profile is active so Spring Boot uses those credentials.

## Step 1 — Start the Backend (IntelliJ IDEA)

1. In IntelliJ, open the `backend` folder.
2. Add / run the Spring Boot `BackendApplication` main class with the
   **`local`** profile:
   - Run configuration → Program arguments:
     `--spring.profiles.active=local`
   - Or simply run from the terminal:
     ```bash
     cd backend
     mvnw spring-boot:run -Dspring-boot.run.profiles=local
     ```
3. Wait until you see something like:
   ```
   Tomcat started on port 8080
   ```
4. Confirm it is listening:
   ```bash
   netstat -ano | findstr :8080 | findstr LISTENING
   ```
   > If port 8080 is already in use by an old process, stop it first:
   > `netstat -ano | findstr :8080` → find PID → `taskkill /PID <pid> /F`,
   > then start again.

## Step 2 — Start the Frontend (VS Code)

1. Open `frontend` in VS Code.
2. Ensure dependencies are installed (once):
   ```bash
   cd frontend
   npm install
   ```
3. Start the dev server:
   ```bash
   npm run dev
   ```
4. Vite prints the local URL, e.g.:
   ```
   Local: http://localhost:5173/
   ```

## Step 3 — Open the Website

Open **http://localhost:5173/** in your browser (Chrome/Edge).

The Vite dev server proxies `/api` requests to the backend on `:8080`, so the
React frontend and Spring Boot backend are wired together automatically.

- **Sign In** → `Login` page
- **Create Account** → `Register` page
- Both hit `http://localhost:5173/api/users/...` → proxied to `:8080`.

## Architecture (how the pieces connect)

```text
Browser opens  http://localhost:5173   (React app served by Vite)
      │
      │  /api/*  (Vite dev proxy → changeOrigin: true)
      ▼
Spring Boot backend  http://localhost:8080   (run from IntelliJ)
      │  JDBC
      ▼
MySQL  aicip_db  :3306   (local profile credentials)
```

The frontend never calls `:8080` directly — it uses the relative `/api` base,
and Vite's `proxy` option in `vite.config.js` forwards those calls to `:8080`.

## Troubleshooting

| Symptom                                 | Fix                                                                                         |
| --------------------------------------- | ------------------------------------------------------------------------------------------- |
| "Network error" on Sign In / Register   | Backend not running or stale. Stop port 8080 process, restart backend with `local` profile. |
| Browser shows old UI / labels invisible | Hard-refresh (Ctrl+Shift+R). The daylight fix is now in `Input.css`.                        |
| Port 8080 already in use                | `netstat -ano \| findstr :8080` → `taskkill /PID <pid> /F` → restart backend.               |
| Port 5173 already in use                | `npm run dev -- --port 5173` or change Vite port in `vite.config.js`.                       |
