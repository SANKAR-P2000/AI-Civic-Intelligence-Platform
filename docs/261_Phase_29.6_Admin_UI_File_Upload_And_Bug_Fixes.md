# 4. Frontend Changes

## 4.1 File Upload in the Complaint Form

- `Complaints.jsx` now includes an optional photo field (JPG/PNG, ≤ 5 MB).
- On submit, if a file is selected, `uploadComplaintImage(file)` uploads it
  first, then the returned filename is passed as `imageUrl` to
  `complaintService.createComplaint`.
- A live preview is shown before submission.

## 4.2 Admin Complaint Management

- New route `/admin/complaints` (protected with `roles={["ADMIN"]}`).
- Lists all complaints via `complaintService.adminGetAllComplaints()`.
- Supports keyword search via `adminSearch(keyword)`.
- Supports status filtering via `adminGetByStatus(status)`.
- Supports inline status updates via `adminUpdateStatus(id, status)`.

## 4.3 Admin Analytics

- New route `/admin/analytics` (protected with `roles={["ADMIN"]}`).
- Loads category, status, and location analytics in parallel.
- Renders them as CSS bar charts (no external chart library).

## 4.4 Routes

`AppRoutes.jsx` now registers both admin routes, each wrapped in a
`ProtectedRoute` that enforces the `ADMIN` role.

## 4.5 Navigation

`Navbar.jsx` now shows admin links (Dashboard, Manage Complaints, Analytics)
when the authenticated user has the `ADMIN` role.

# 5. Backend Changes & Bug Fixes

## 5.1 Bug Fix — Hard-Coded Image URL

**Before:** `ComplaintServiceImpl.mapToResponse` returned image URLs as
`http://localhost:8080/uploads/<file>`, which broke in production and behind
the Vite proxy.

**After:** It now returns a **relative** URL:

```java
response.setImageUrl("/uploads/" + complaint.getImageUrl());
```

This works in dev (proxied by Vite) and in production (served by the same
Spring Boot host). The `WebConfig` already maps `/uploads/**` to the
`uploads/complaint-images` directory, and `SecurityConfig` permits
`/uploads/**`.

# 6. Real-Time Integration Flow

1. **Citizen** submits a complaint with an optional photo.
2. The image uploads to Spring Boot; the stored filename becomes the
   complaint's `imageUrl`.
3. The complaint is saved to `complaints` and an email notification is sent.
4. **Admin** logs in and navigates to `/admin/complaints` to search, filter,
   and update statuses.
5. **Admin** opens `/admin/analytics` to view category/status/location
   breakdowns.
6. Images are served from `/uploads/**` and render correctly in dev and
   production.
